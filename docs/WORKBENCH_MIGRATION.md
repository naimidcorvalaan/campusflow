## 1. 正式信息架构

正式入口仍为 `src/p2_live_main.py`。左导航为「今天」「时间线」，材料估时位于辅助工具区；个人设置、校区与时间在底部。默认校区仍为北洋园。

有计划时：当前安排 → 下一安排 → 重新规划 / 更新变化入口 → 后续安排预览。右侧独立呈现下一固定安排、对应路线出发和到达时间、下一段校园移动及准备时间。无计划时呈现原自然语言规划表单。

校区与时间控件按需展开，原控件 key、校区映射和时间来源规则不变。品牌恢复固定副标题「tjuer专属的校园时空规划系统」。

## 2. 当前行动

当前安排使用蓝色顶线、38px 任务标题和58px 本段分钟数。任务、结束时间、地点和下一项集中在同一区域；右侧约束安静地排列在画布上。主信息没有整圈圆角卡片，不为静态展示添加假点击反馈。

分钟数由已发布当前行动的结束时间与该计划的参考时间投影；不猜测未知时长。固定安排与移动信息直接读取已发布 commitments / movement_blocks，不调用路线或规划器。

## 7. 文案与操作语义

采用「当前安排」「下一固定安排」「安排依据」「更新变化」「待确认」「缺少必要信息」。去掉反馈示例 chips 和常驻能力解释，设置说明压缩为保存与覆盖规则。自动食堂标记简化为「就近食堂」，保留事实含义；暂估标记仍保留不确定性。

站内移动不使用外链箭头。全局 THINKING、局部 THINKING....... 继续保留。上传提示按实际文字节点本地化，同时移除重复伪元素文案。

## 8. hover / pressed

主按钮实心蓝、次按钮中性描边、轻操作透明底。真实按钮按下使用 `scale(.978)`、下沉1px、`brightness(.9)` 和内阴影；过渡约120–150ms，释放回弹。原生可点击展开行、导航和设置控件有克制反馈，静态时间行不响应 hover。

实测按住主按钮时，computed transform 为 `matrix(0.978, 0, 0, 0.978, 0, 1)`，filter 为 `brightness(0.9)`，阴影为 inset。尊重 reduced-motion。

## 9. 旧视觉清理

移除 `p2_live_main.py` 大段旧 `_TOP_INPUT_CSS`、`p2_main.py` 旧卡片/时间线CSS和材料结果重复皮肤。正式主题统一来自 `src/workspace.css`；`campusflow_ui.py` 继续提供原品牌与无障碍桥接。正式运行不读取 prototype，也不依赖 prototype server。

## 10. rerun 与状态保护

导航只改变展示状态和容器可见性，主表单、反馈、材料工具仍挂载；不复制上传文件，不新增业务状态机。浏览器核对导航前后整个已发布计划指纹一致、调用数不增；What-if采用前指纹不变，采用后按原原子入口发布。

浏览器发现并修复两处 native widget 生命周期问题：

- 设置关闭的提前 rerun 会清除服务端上传对象，即使页面仍显示旧文件名。`DeferredDrawerRerun` 终止抽屉本轮渲染，但让主控件先挂载，再执行原 rerun；Profile切换仍发生在目标控件初始化前。
- 重开设置时，已移除日期控件可能反序列化为默认日期，使 setdefault 无法恢复草稿。仅在重开时恢复显式留存值；普通 rerun 保留最新编辑。导入控件改为一次初始化状态，不同时提供另一份动态默认值。

新增回归覆盖导航不触发调用/不改变发布对象、连续时间线、路线真实出发时间、延迟 rerun 顺序、日期草稿恢复。未修改 planner、P5决策、task refs、progress/completed、SQLite schema、地图或公网/OIDC。
