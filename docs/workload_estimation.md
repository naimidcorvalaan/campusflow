# 独立工作量估时（2026-09-12）

本记录替代 `estimate_recovery.md` 历史记录中的“两次回复都无分钟便返回估时失败”。没有取得用户原始测评表或失败时的真实模型响应；以下是代码路径复现、合成材料及离线模型验证，不是真实 TJU 验收。

## 根因

上一版虽然可以从损坏的正式结构中保留合法 estimate，但并没有独立保存“不带分钟的工作量”。两次调用都要求模型同时完成材料理解和有效估时；只要模型省略 estimate、给出非法数字或把动作标为 false，合法表格字段就没有后续计算路径，最终落入 estimate_unavailable。正式结构、动作判断和分钟校验仍共用成败结果。

“填表”已通过请求快照进入 supplemental_context，并非只在页面回显。本轮在主请求和短估时请求的实际调用边界分别断言该值，并在真实 Streamlit 离线页面记录安全请求摘要；不记录原文或完整模型响应。不能据此声称知道用户那一次真实模型具体返回了哪个错误字段。

## 新状态流

材料读取 → 保存可识别工作量 → 解析主理解结果中的工作量 → 为已有工作量确定时间 → 尽力保留正式事项 → 原确认门禁。

- `src/material_workload.py` 持有独立 Workload/Feature。文本型来源先从实际空白字段、评分槽、写作要求等提取；图片及复杂材料由统一主调用提取带引用的特征。识别不依赖 Task、deadline、location、coverage 或合法分钟。
- `src/material_intake_pipeline.py` 替换原编排块，分别接收工作量和正式结构。正式解析器只产生可选结果；任何正式解析失败都不能撤销已识别工作量。即使正式结果只剩固定安排，实际填写工作仍须估时。
- 当前 Recognition Function 通道只识别任务与工作量，不生成历史可选估时。独立估时处理范围、特征、补充和正式来源事实，最多一次建议和一次有界修复，仍经过同一套正式校验。输出上限 2048 tokens，超时 30 秒；原 768 上限因完整 ledger 输出截断而调整。全文识别与补充后重识别保持现有产品行为。
- 短调用空、非法或网络失败时，对同一份已识别工作量直接计算保守区间。它不是再次识别或再次尝试生成 Task。每份有效 Workload 的 resolve 都返回时间，编排末尾检查 `没有工作量 or 已有时间`。
- 主理解尚无任何工作量时，可再做一次材料理解修正；纯参考、不可读、完全无法判定动作才可没有时间。一般一次或两次调用，最坏一次主理解、一次识别修正、一次短估时，共三次，无递归重试。
- 既有正式事项在原校验器中尽力整理并保留；独立估时只作为展示结果，不把局部分钟附到更宽的正式范围，不创建 refs、deadline、location 或 completed。加入计划仍需原确认和原子发布。

因此，“测评表 + 填表”只要读取结果已经包含实际可填字段，就会在模型回复之前留下 Workload。后续即使两个模型回复均为 `{}`、非法 JSON 或否认动作，也必然得到该 Workload 的保守区间；不是依赖模型服从“必须估时”提示词。文件名或“填表”两个字本身不能替代可读证据。

## 粗估如何计算

以下为可调整、尚未用学生实测数据校准的工程先验，页面明确标为保守粗估，不是精确承诺。按实际识别数量逐项相加，再向上取整，建议值取区间中点。

| 已识别单位 | 每单位专注分钟区间 |
| --- | --- |
| 基础字段 | 0.3–1 |
| 选择或评分项 | 0.5–2 |
| 短文本项 | 2–6 |
| 长主观文字 | 10–30；有明确字数时按每分钟 10–35 字计算 |
| 回忆经历 | 3–12 |
| 查资料 | 5–20 |
| 准备附件或证明 | 3–10 |
| 复核 | 2–6 |
| 明确要求阅读的已识别文字 | 每百字 0.5–2 |
| 识别到的题目 | 每题 3–15 |

不按文件名、文件大小、页数或任意表格行数计时。未知列仅在明确填表意图下估计填写一条记录，范围明示。外部签字、审批和等待不计入。没有明确字数时不虚构字数；模型对文本来源给出的引文、数量和字数须通过来源校验。

本轮合成测评表实际有 2 个基础字段、5 个评分项、约 300 字自我评价、回顾经历、1 个证明名称短文本栏、准备证明和复核。全部模型不给分钟时计算为 **22–76 分钟，建议 49 分钟**。这是该合成工作量的结果，不是“表格固定分钟”，也不是用户原文件的预测。

独立工作量结果保守标明“目前识别到的部分”，完整任务可能更久。页面首先展示做什么、时间和依据；粗估的覆盖与等待各说明一次，补充框默认收起。沿用单一输入区、稳定组件位置、冻结提交快照，补充不会因处理中或完成而清空。

- 正式确认、stable refs、progress/completed、发布失败回滚等原回归继续通过。没有真实 TJU 调用，没有创建 Agent，没有操作地图/P5/公网/OIDC/NEMU，没有提交、推送或清理现有修改。

## 唯一一次真实验收

重启当前本地 CampusFlow，在同一会话上传原始“本科生综合素质测评考核表【主观评价部分】.docx”，不补充说明点击“帮我看看”；查看实际工作、区间、依据及部分范围说明。随后展开“补充我的情况”，输入“填表”并重新估算：应仍有时间，处理前中后只有一套输入，完成后“填表”仍在。不需要加入计划，也不预设固定分钟。
