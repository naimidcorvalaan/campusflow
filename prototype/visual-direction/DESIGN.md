# CampusFlow：今日工作台

> 历史提案归档：公开版保留交互原型与[四张设计归档图](../../docs/assets/design-history/)。下文 `screenshots/` 中的原始测试图与 JSON 仅本地保留，可通过 `check.cjs` 重新生成。

视觉方向提案 · 2026-09-12 · 桌面 1440 × 900

这是一份可以交互的独立设计原型。打开 `index.html` 即可使用，无需构建、安装依赖或配置 API；也可以从本地静态服务打开。底部 A—F 是评审工具，不属于拟议中的产品界面。

本轮只新增 `prototype/visual-direction/`。正式页面、材料估时、planner、P5、地图、SQLite、用户状态、任务引用、原子发布和 API 均未修改。原型中的计划、用时、文件与课表均为示例，所有编辑只保留在页面内存中。真实文件选择仅演示选择交互，不读取或解析内容。

## 设计判断

CampusFlow 应该像学生每天打开的一张工作台：进入之后，先看见现在最值得做的事，再看接下来怎么衔接。工具和设置都容易找到，但不需要每次打开都介绍自己。

新的气质是：浅色、清楚、有边界、稍有活力。蓝色负责指向行动；线条负责组织信息；留白负责区分重要程度。无需用大量装饰证明它是一个 AI 产品。

## 当前页面的五个具体问题

这些判断来自当前代码及实际浏览器观察，不是根据旧版本印象。基线提交为 `423bae50f323b7247a28d2e1ddc7564424c1f9fe`，启动既有离线入口，使用正式渲染组件与 mock 模型，观察空首页、已生成计划和设置。截图位于 `screenshots/current-*.png`。

1. **外框承担了太多层级工作。** `src/p2_main.py` 将当前行动、时间线和侧栏统一放入 `.cf-plan-hero, .cf-timeline-card, .cf-side-card` 的白底、边框和圆角体系；输入表单又采用类似包装。用户首先看见一排“模块”，其次才看见它们的职责。
2. **顶部环境控制占据了过高的视觉优先级。** 校区选择、时间设置、参考时间和说明先占据完整一行甚至多行。每天使用时，这些通常是背景条件，不该和主要任务竞争。当前新建表单和已有计划还共享同一条纵向页面路径，状态间缺少整体变化。
3. **当前行动与反馈表单的主次不够悬殊。** 当前任务名、下一事项已存在，但紧接着又是“标题＋解释＋示例 chips＋输入＋蓝按钮”的完整反馈模块，时间线被进一步推下去。反馈应该贴近当前行动，以一个明确入口按需展开。
4. **无计划首页仍像功能展示页。** 四项能力介绍采用同样的图标、粗标题、解释句。当前代码已把它们限制在无计划时显示，并非已有计划仍常驻；本提案进一步取消这四栏，只留输入示例和一条可用的估时入口。
5. **操作的外观分类不足。** 原生主按钮/次按钮承担太多不同意义，换材料、补充、编辑等轻动作常成为描边按钮；目前有 hover，却缺少统一的按下反馈。设置仍以展开项、大控件、解释段落纵向堆叠，缺少连续行的扫描节奏。

## 新视觉语言

### 布局与颜色

- 桌面左导航 196px；顶部工具栏 76px；内容两侧留白 46px。主区域与 215—248px 的次区域形成不对称结构。
- 画布 `#FAFBF9`，导航 `#F0F2EF`，工作表面 `#FFFFFF`。避免整个页面使用浅蓝底。
- 产品强调蓝 `#2157A0`；正文 `#20272D`；辅助文字 `#687078`；分隔线 `#E0E3E4`。绿色 `#477461` 用于低强度的休息/环境提示，错误使用独立的暗红语义。
- 蓝色与天大校园语境保持联系，但这个产品色值不宣称是官方 VI 数值。不使用校徽来暗示官方身份。
- 中文使用本地系统字体，无字体 CDN。正文以 14px 为基准，次信息 12px；分组标题 16px，页标题 30px，当前任务 38px，空首页 46px，核心时间 60px。数字使用等宽数字特性。
- 节奏基于 4/8/12/16/24/32px；区域之间比区域内部留更多空白。

### 组件身份

| 对象 | 形态与权重 | 是否有触感 |
| --- | --- | --- |
| 当前行动 | 一个开放的白色行动区，蓝色顶线，大任务名与大时间数字；没有环绕圆角框 | 整个信息区不动，内部动作按钮有反馈 |
| 下一安排 | 一行信息，左标签、中间任务与时段、右侧详情 | 只有明确的详情操作可点击 |
| 时间线 | 连续时间列、细线、节点；任务、出行、固定课用不同密度和节点区分 | 普通时间行保持静态 |
| 次要信息 | 直接放在右侧画布上，用分隔线组织 | 无伪按钮反馈 |
| 材料估时 | 独立的工具工作区，8px 圆角；文件行、时间、依据列表和补充区 | 输入与真实操作响应，估时数字不响应 |
| 设置 | 连续行＋分组留白；标签和值左右对齐；只有编辑区域使用控件底色 | 原生选择器和可点击行反馈 |
| 提示 | 一条窄色线或低饱和背景，贴近相关区域 | 默认不可点击 |
| 错误 | 在出错输入或操作附近显示文字与暗红边线；保留原结果 | 重试是次操作，不能把整页变成红色卡片 |
| 可点击行 | 背景轻变，必要时有末尾箭头 | 整行轻微收缩，不抬高 |
| 普通文本 | 无边框、无手型、无 hover | 不动 |

### 操作层级与触感

- Primary：实心蓝、6px 圆角。用于当前最重要的一次提交，如“帮我安排”“更新进度”。同一区域原则上只有一个。
- Secondary：细描边、5px 圆角。如“重新估算”、次级确认操作。
- Quiet：无常驻边框、3px 反馈底色。如更换、补充、编辑、说明、查看详情。
- 图标按钮：圆形命中区，如设置关闭 ×。仅用在无需文字也清楚的操作，并提供可访问名称。

主按钮状态：正常 `#2157A0` → hover `#1C4D8E` → pressed `#173E72`。按下时 `translateY(1px) scale(.975)`，外侧轻阴影改为内凹。可点击行只缩至 `.992`。恢复时长 160ms，没有弹簧过冲。只影响绘制，不触发布局位移。

真实鼠标按下测得 `matrix(0.975, 0, 0, 0.975, 0, 1)`，`:active=true`，阴影包含 `inset`；释放后为 `transform:none`。原型 F 可亲自按住体验，`screenshots/touch-hover-1440.png`、`touch-pressed-1440.png`、`row-pressed-1440.png` 是实际交互截图，不是手工改状态类生成的图。

键盘保留焦点描边；减少动态效果时禁用位移和缩放，仍保留颜色反馈。禁用按钮不产生按压效果。

## 新旧信息架构

| 场景 | 当前 | 提案 |
| --- | --- | --- |
| 无计划首页 | 品牌 → 校区/时间 → 输入表单 → 四栏能力介绍 → 估时展开项 | 轻导航/环境信息 → 一个直接问题与输入区 → 示例输入 → 一行估时工具入口 |
| 已有计划 | 品牌/环境 → 重排入口 → 当前行动 → 完整反馈表单 → 时间线与提示 → 估时 | 当前行动成为首屏中心；下一安排贴近当前；固定课与出发时间在右侧；下方展示余下概要；反馈按需展开 |
| 时间线 | 首页卡片中的完整列表，与其他模块共用纵向空间 | 有独立视图，连续时间列，出行和准备保留明细；首页只露出关键摘要 |
| 估时 | 首页统一展开容器 | 左导航稳定入口，空首页额外露出一行；展开后进入工具工作区，返回今天不改变计划 |
| 设置 | 右侧面板内的大控件和说明段落 | 保留右侧覆盖面板；偏好/地点/课表三组；连续设置行与底部保存区 |

### 删除、弱化和移动

- **删除四栏能力介绍。** 不是删功能，是让已有功能变成能直接用的入口和输出。空状态只有示例输入和一句设置提示，不重复宣传。
- **弱化品牌副标题。** 品牌保持可辨认，删除“专属校园时空规划系统”式大定位句；导航中的短说明没有主视觉地位。
- **移动校区和时间控制。** 顶栏显示当前环境，需要修改时再进入相关控件。正式实施仍必须保留时间来源和手动参考时间的可见性，不能只显示一个无来源的钟点。
- **移动完整反馈表单。** 当前行动上的“更新进度”和安静的变化入口打开短输入层；保留原反馈与试排/采用语义，不新增自动提交。
- **移出完整时间线。** 首页保留下一安排与重要节点；独立时间线保留所有路程、收拾、准备、空档和固定课，并非删掉细节。
- **移动估时。** 辅助工具入口随时可见，已有计划时不和当前行动争面积；估时结果也不自动加入计划。
- **弱化泛化提示。** 用一个紧邻固定安排的安静提示替代等高侧栏提示卡；只有实际相关的信息出现。

## 下一步映射到 Streamlit 的风险

1. **组件身份与 rerun。** 不能因切换工作区重建原上传框、改 widget key/default value 或打断补充快照。应重排渲染容器，保留原 handlers 与 session state；尤其回归材料处理中不得有 stale DOM 双组件。
2. **导航隐藏控件可能触发状态清理。** 不应把 HTML 原型的整页替换直接照搬成条件渲染。须检查原生控件卸载行为，单独持有未提交草稿，不能让导航清空设置或材料。
3. **设置仍使用原生控件。** 连续设置行可以由 columns/container 排版实现，但设置面板、下拉浮层和日期选择器的 z-index、Escape、Tab、焦点返回要继续验证。不能只做一张 HTML 表单绕开原保存函数。
4. **避免宽泛 DOM CSS。** 当前存在框架内部结构选择器。正式实施应尽量用自己的语义标记做局部作用域；不能把所有 Streamlit 按钮和容器统一改色或缩放。给原生按钮增加按压视觉不应增加提交事件或 rerun。
5. **当前行动不是新计时器。** 本原型没有“开始专注”倒计时或自动完成；“更新进度”仍映射原反馈入口。分钟、已完成量、时间来源、任务引用继续来自原业务数据。
6. **完整时间线只是另一种投影。** 不能为了紧凑重算路程或压缩固定课；摘要与明细必须读取同一已发布结果。试排、采用、保留当前方案仍是分离动作。
7. **估时确认不能被视觉隐藏。** 部分估时、不可读限制、已有任务关联和正式确认继续保留。原型刻意没有在部分估时上加一个醒目的“直接加入”按钮。
8. **对比度与可达性。** 细线只负责辅助分组，不能作为唯一状态标识；主体内容不能缩到评审工具条的小字号。正式落地需验证系统字体、缩放、键盘、减少动态效果及 1440/窄屏布局。

建议实施顺序：确认视觉方向 → 定义 tokens 和按钮层级 → 仅调整现有渲染职责与容器 → 设置分组 → 当前行动/时间线 → 重新运行原语义与真实浏览器回归。本次不执行正式迁移。
